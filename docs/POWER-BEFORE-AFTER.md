## 1. 已经测到的

### 1.1 供电：不是问题（IMG_5738 / IMG_5743）

`MSDC_PS` 的 DAT 在 bits 23..16、CMD 在 bit 24。DAT=0xFF、CMD=1、卡在位；
VEMC 3.0 V（`LDO_VEMC_CON0` en=1，`VEMC_ANA_CON0` vosel=3）。**不要再查供电。**

### 1.2 复用 / pad / 复位：都不是问题（IMG_5744）

`m0=0x22222200`（122..127 全 mode 2，跨重启保持）；`DIN=0xDFB` 只有 CLK 和
`DS`（132，vendor 就是下拉）为低 ⇒ **RSTB 高、DAT 全高**。

### 1.3 关键突破：`CMD0 → CMD1` 有应答（IMG_5747）

```
C0     I=00000100            cl=98  f=297 l=402  kc=14841
PING a I=00000100 R=00FF8080 cl=129 f=13  l=221  kc=15232
```

`I=0x100` = CMDRDY（此前一直是 `0x200` = CMDTMO）；`R=00FF8080` 是 R3 的 OCR。
时间结构：`C0` 帧跨 105 个样本，`PING a` 跨 208 ≈ 2× ⇒ 命令帧 + 响应帧。
**根因：卡不在 idle 状态，`CMD1` 对它是非法命令。**

### 1.4 卡上电完成（IMG_5750）

```
C0     I=00000100 cl=97  f=297 l=402 kc=14767
PING a I=00000100 R=00FF8080 cl=125 f=15 l=222 kc=15187
C1 n=1 I=00000100 R=C0FF8080
```

- `C1 n=1`：第一轮 `CMD1` 的 OCR 就带 **bit31=1**（上电完成）、bit30=1（扇区模式）。
  `n=1` 说明"重复 CMD1 直到 ready"的循环一轮就满足了。
- **`C1` 之后没有文字，不是失败**：文字区只有 68 行（y 0..1087），
  `DandelionConsoleDxe` 自己的自检把光标留在第 53 行，本驱动只剩 15 行预算；
  上一版要吃 21 行，于是 `C2..C13` 全被画到最后一行之外。
  这一版把旧诊断压成 3 行、整段只占 10 行。

## 2. 本版（V9）做什么

IMG_5753 把上一版的两条假设都否掉了：

```
C13 I=00000100 R=00000900 st=4
C6  I=00000100/00000100 n=1 st=4      ← CMD6 两条都被接受，卡回到 TRAN
C8  I=00000100 sz=00000000 ...        ← 数据相位还是根本没开始
stop I=00000200                        ← CMD12 超时（卡当时没在传，所以正常）
```

dtype 已经在 bit 11（命令字 `0x02000888`，与 vendor 一致），卡也接受了 CMD6，
1-bit + default speed 的组合**依然没有数据**。所以“模式不匹配”不是全部原因，
真正要回答的是：**数据总线上到底是谁没说话。**

这一版就回答这个，一次刷机跑三种模式：

| 行 | 主机 | 卡 | 含义 |
|---|---|---|---|
| `A8` | 8-bit | LK 留下的（8-bit HS200） | **bootshim 用的那套**，已知能读写 |
| `B8` | 8-bit | CMD6 `HS_TIMING=0` | 8-bit default speed |
| `C8` | 1-bit | CMD6 `BUS_WIDTH=0` | 上一版失败的那个组合 |

哪一行先成功，后面的就不跑了；成功时再读 LBA 1 打 `B1`。

每行格式：

```
A8 I=00000100 sz=00000000 ps=FF/FF f=00 c6=0000
             |         |      |    |     |
             |         |      |    |     └ CMD6 的 INT（没切就是 0000）
             |         |      |    └ FIFOCS.RXCNT 残留：非 0 = 确实收到字节
             |         |      └ DAT[7:0] 一直为高 / 曾经为高（整个等待窗口累加）
             |         └ EXT_CSD 的 SEC_COUNT（读成功才有意义）
             └ MSDC_INT：...0100 只有 CMDRDY；...1100 有 XFER_COMPL；...4100 有 DATTMO
```

`ps=FF/FF` ⇒ 控制器**从没看见卡驱动数据线**；`ps=FE/FF` ⇒ DAT0 曾经为低，
**卡在发、主机没接住**。这两种情况的下一步完全不同，必须分开。

## 3. 判读表（V9）

| 画面 | 结论 | 下一步 |
|---|---|---|
| 任一行 `I=...1100` 且 `sz` 非零、`B1 S=45464920` | **数据通路打通**，记下行号就是可用模式 | 把这套模式搬进驱动 |
| `A8 I=...0100 ps=FF/FF`（三行都这样） | 卡根本没驱动 DAT ⇒ 卡侧（模式/供电/未完成上电） | 再查 `EXT_CSD` 可达性 / 换 4-bit 试 |
| `... ps=FE/FF` 或更低 | 卡在发、主机没接住 ⇒ 主机数据通路 | `SDC_FIFO_CFG` / `MSDC_IOCON` / `SDC_ADV_CFG0` |
| `f=` 非 0 | 字节到了 FIFO，是 drain 或中断的问题 | 看 `XFER_COMPL` 位 |
| `I=...8100`（DATCRCERR） | 采样窗口不对 | `MSDC_PAD_TUNE0` |
| `B1 -` | 三种模式都没成 | 按上一行的 `ps=` 分叉 |
| 某行 `I=00000200` | 那条命令超时 | 看它上一行 |



## 4. 这一版**没有**写什么

- 不写 PMIC、不改总线宽度、不改时钟分频、不做 DMA/tuning。
- 会写卡状态的只有规范里的初始化命令：`CMD0`、`CMD1`×n、`CMD2`、`CMD3`、`CMD7`、
  `CMD13`、`CMD16`、`CMD8`、`CMD17`；全部有界超时。
- 唯一的寄存器写：GPIO122..133 的 mode（写回它本来就该有的 mode 2）、
  `MSDC_CFG.PIO`（幂等）。
