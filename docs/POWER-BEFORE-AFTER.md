## 1. 已经测到的

### 1.1 供电：不是问题（IMG_5738 / IMG_5743）

`MSDC_PS` 的 DAT 在 bits 23..16、CMD 在 bit 24。DAT=0xFF、CMD=1、卡在位；
VEMC 3.0 V（`LDO_VEMC_CON0` en=1，`VEMC_ANA_CON0` vosel=3）。**不要再查供电。**

### 1.2 复用 / pad / 复位：都不是问题（IMG_5744）

`m0=0x22222200`（122..127 全 mode 2，跨重启保持）；`DIN=0xDFB` 只有 CLK 和
`DS`（132，vendor 就是下拉）为低 ⇒ **RSTB 高、DAT 全高**。

### 1.3 关键突破：`CMD0 → CMD1` 有应答（IMG_5747）

```
C0     I=00000100            cl=98  f=297 l=402  kc=14841
PING a I=00000100 R=00FF8080 cl=129 f=13  l=221  kc=15232
```

`I=0x100` = CMDRDY（此前一直是 `0x200` = CMDTMO）；`R=00FF8080` 是 R3 的 OCR。
时间结构：`C0` 帧跨 105 个样本，`PING a` 跨 208 ≈ 2× ⇒ 命令帧 + 响应帧。
**根因：卡不在 idle 状态，`CMD1` 对它是非法命令。**

### 1.4 卡上电完成（IMG_5750）

```
C0     I=00000100 cl=97  f=297 l=402 kc=14767
PING a I=00000100 R=00FF8080 cl=125 f=15 l=222 kc=15187
C1 n=1 I=00000100 R=C0FF8080
```

- `C1 n=1`：第一轮 `CMD1` 的 OCR 就带 **bit31=1**（上电完成）、bit30=1（扇区模式）。
  `n=1` 说明"重复 CMD1 直到 ready"的循环一轮就满足了。
- **`C1` 之后没有文字，不是失败**：文字区只有 68 行（y 0..1087），
  `DandelionConsoleDxe` 自己的自检把光标留在第 53 行，本驱动只剩 15 行预算；
  上一版要吃 21 行，于是 `C2..C13` 全被画到最后一行之外。
  这一版把旧诊断压成 3 行、整段只占 10 行。

## 2. 本版（V13）做什么

IMG_5759（V12）读数：

```
RST C=0200F09B
H0 C=0200F09B S=FF007FFC P=81FF0002 N=00000001
IO dir=000 do=000 din=00000DF7
A8 I=0100 R=00000900 sz=00000000 ps=EF/FF gp=DF8/DFF f=00 k=14994 c6=00000000
B8 I=0100 R=00000900 sz=00000000 ps=EF/FF gp=DF8/DFF f=00 k=15061 c6=00000900
C8 I=0100 R=00000900 sz=00000000 ps=EF/FF gp=DF8/DFF f=00 k=14933 c6=00000900
D8 I=0100 R=00000900 sz=00000000 ps=EF/FF gp=DF8/DFF f=00 k=1504x c6=00000000
B1 -  no data phase
```

结论有三条，都是否定的：

1. **软复位没用**（`RST C=0200F09B` 与复位前一致，说明复位干净且已回到同一配置）；
2. **CKPDN 不是原因**（`D8` 清了也一样）；
3. **时钟一直在跑**（`k≈15000/30000`），所以“没时钟”的假设也死了。

同时 `c6=00000900` 说明 **CMD6 切换被接受、无 SWITCH_ERROR**；`R=00000900`
说明卡在 TRAN + READY_FOR_DATA、无错误位。**卡一直很好，就是不驱动 DAT。**

于是这一版只问一个问题：**卡自己认为传输开始了没有？**

数据命令失败之后立刻补一条 `CMD13`，把状态打出来：

| 字段 | 含义 |
|---|---|
| `t=` | CURRENT_STATE：**4 = TRAN**（卡根本没开始传）／**5 = DATA**（开始了、正在被时钟推数据，丢在主机侧） |
| `r=` | READY_FOR_DATA |

这一个数字决定下一步的方向：

- `t=5` ⇒ 主机侧接收路径（pad 的输入使能 / OE），下一步用 `AddMemorySpace` 映射
  `0x10002000` 去读/修 pad；
- `t=4` ⇒ 卡确实没开始，转去卡侧（`EXT_CSD` 可达性、分区访问、卡是否被永久锁定）。

## 3. 判读表（V13）

| 画面 | 结论 | 下一步 |
|---|---|---|
| 任一行 `I=1100` + `sz` 非零 + `B1 S=45464920` | **数据通路打通** | 按该行模式改驱动 |
| `t=5` | 卡在发、主机没接住 | 映射并检查 MSDC0 pad（IES/OE） |
| `t=4` | 卡没开始传 | 查卡侧：EXT_CSD 可达性 / 分区访问 / 卡状态 |
| `t=0` | CMD13 都没发出去 | 控制器还卡在数据相位（SDCBUSY），说明它确实在等数据 |
| `R=` 带错误位 | 卡拒绝 | 按位查 |
## 4. 这一版**没有**写什么

- 不写 PMIC、不改总线宽度、不改时钟分频、不做 DMA/tuning。
- 会写卡状态的只有规范里的初始化命令：`CMD0`、`CMD1`×n、`CMD2`、`CMD3`、`CMD7`、
  `CMD13`、`CMD16`、`CMD8`、`CMD17`；全部有界超时。
- 唯一的寄存器写：GPIO122..133 的 mode（写回它本来就该有的 mode 2）、
  `MSDC_CFG.PIO`（幂等）。
